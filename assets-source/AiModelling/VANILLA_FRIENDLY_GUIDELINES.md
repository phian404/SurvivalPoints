# Vanilla-Friendly Guidelines — SurvivalPoints

**Цель:** все модели и текстуры мода должны выглядеть так, будто они являются частью оригинального Minecraft Java Edition 1.20.1.

Эти правила применяются ко всем новым моделям, блокам, предметам и текстурам.

## 1. Общий стиль

- Ориентироваться на оригинальную графику Minecraft Java Edition 1.20.1.
- Простая геометрия, выразительный силуэт, детали преимущественно через текстуры.
- Не использовать реалистичные фотографии, гладкие материалы и современный PBR-стиль.
- Не перегружать модели мелкими деталями.
- Избегать избыточного количества кубов и граней.
- Сохранять характерную для Minecraft пиксельную графику.

## 2. Геометрия моделей

- Стандартный размер блока Minecraft — 16×16×16 единиц.
- Стараться использовать минимально необходимое количество элементов.
- Не создавать отдельные кубы для каждой мелкой детали, если её можно передать текстурой.
- Не использовать множество мелких кубов для имитации плавных изгибов.
- Повороты элементов применять осмысленно.
- Избегать чрезмерно мелких элементов и несогласованного масштаба деталей.

## 3. Плоскости и прозрачные текстуры — приоритетный способ оптимизации

Для сеток, решёток, ограждений, перфорированных панелей и других объектов с повторяющимся рисунком предпочитать одну большую тонкую плоскость с текстурой вместо множества отдельных геометрических элементов.

Пример: металлическая сетка забора.

Вместо сотен маленьких кубиков, изображающих переплетение проволоки:
1. Создать одну тонкую панель нужного размера.
2. Подготовить PNG-текстуру с изображением металлической сетки.
3. Металлические линии сделать непрозрачными.
4. Отверстия между линиями сделать полностью прозрачными (Alpha = 0).
5. Наложить текстуру на панель через корректную UV-развёртку.

### Правила прозрачности

- Использовать PNG с альфа-каналом.
- Для обычных отверстий использовать полностью прозрачные пиксели, а не полупрозрачные.
- Для таких моделей на Forge 1.20.1 использовать подходящий render type, обычно `minecraft:cutout`.
- Проверять отображение с обеих сторон.
- Следить, чтобы соседние плоскости не пересекались и не создавали визуальных артефактов.
- Не превращать всю поверхность в полупрозрачное стекло, если нужны обычные отверстия.

Применять этот подход там, где он действительно подходит. Не заменять плоскостями элементы, которым необходим объёмный силуэт.

## 4. Когда нужна объёмная геометрия

Настоящую геометрию использовать для:
- спиральной и обычной проволоки;
- выступающих шипов и креплений;
- труб, кабелей и объёмных конструкций;
- деталей, чей силуэт существенно меняется при повороте камеры;
- элементов, которые должны отбрасывать собственную тень и выглядеть объёмными.

Например, спиральная колючая проволока должна иметь настоящие объёмные витки. Её не следует изображать одной плоской текстурой.

## 5. Текстуры

- Использовать чёткий пиксельный рисунок.
- Не применять размытие и сглаживание.
- Не использовать случайный шум ради детализации.
- Не злоупотреблять градиентами.
- Сохранять согласованную плотность пикселей.
- Не растягивать и не сжимать рисунок при UV-развёртке.
- Использовать ограниченную цветовую палитру.
- Для одного материала обычно достаточно базового цвета, оттенка тени и оттенка света.
- Размеры 16×16 и 32×32 допустимы, если разрешение соответствует масштабу модели и не нарушает общий визуальный стиль.

## 6. Материалы

**Металл:**
- Сдержанные серые и холодные оттенки.
- Отдельные пиксельные блики и тени.
- Ржавчина и повреждения — умеренно.

**Дерево:**
- Небольшое количество оттенков.
- Читаемое направление волокон.
- Без фотореалистичной текстуры.

**Бетон и камень:**
- Чёткие пиксельные пятна и трещины.
- Умеренная вариативность.
- Без случайного цифрового шума.

**Сетка и решётки:**
- Хорошая читаемость металлических линий.
- Прозрачные отверстия.
- Минимальная геометрия.

## 7. Работа с ванильными образцами

Использовать оригинальные ресурсы именно Minecraft Java Edition 1.20.1 как визуальные и технические ориентиры.

Создать при необходимости небольшую библиотеку:

`assets-source/AiModelling/vanilla-reference/1.20.1/`

Собирать туда только полезные образцы:
- модели железных прутьев;
- цепи;
- паутины;
- железных и каменных блоков;
- стекла;
- других подходящих ванильных объектов.

Не нужно копировать весь набор ресурсов Minecraft. Достаточно релевантных примеров.

Сравнивать новые модели с оригинальными объектами по геометрии, палитре, плотности пикселей и общему стилю.

## 8. Проверка моделей

Перед завершением каждой модели:

1. Проверить её при обычном игровом масштабе.
2. Посмотреть спереди, сбоку, сверху и под углом.
3. Проверить прозрачность текстур.
4. Проверить UV-развёртку.
5. Проверить стыковку соседних блоков.
6. Проверить повторение текстур на участке 3×3 блока, если объект повторяется.
7. Сравнить с подходящими ванильными образцами.
8. Убедиться, что модель не перегружена геометрией.

## 9. Главный принцип принятия решений

Перед созданием каждой детали задавать вопрос:

**Можно ли передать эту деталь текстурой на одной плоскости вместо создания множества кубов?**

Если да — предпочитать плоскость и прозрачную текстуру.

Если деталь должна иметь настоящий объём, изменять силуэт при взгляде с разных сторон или выступать из поверхности — использовать геометрию.

Не упрощать модель настолько, чтобы она теряла узнаваемость.

## 10. Приоритет качества

При создании моделей соблюдать следующий порядок:

1. Правильный и узнаваемый силуэт.
2. Соответствие визуальному стилю Minecraft.
3. Правильные пропорции.
4. Качественная пиксельная текстура.
5. Оптимальное количество геометрических элементов.
6. Корректная работа в Minecraft Forge 1.20.1.

Эти рекомендации являются постоянным визуальным стандартом проекта SurvivalPoints.

Перед созданием новых моделей и текстур Roo Code должен учитывать этот документ.

**Важно:** документ устанавливает правила оформления, но сам по себе не разрешает изменять игровые ресурсы, Java-код, MCP или существующие модели. Изменения выполняются только в рамках отдельно поставленных задач.
