## 2. Тематика и замысел

Постапокалипсис. Выжившие обустраивают **лагерь** (забор, ворота, теплица с фермой, ловушки, вышки), а **стражи** (`BaseGuardianEntity`) его охраняют: стоят на постах, отстреливают подходящих врагов, зовут союзников, ночью лагерь закрывается.

Лагерь — **общий для мира**, не принадлежит игроку; при этом допускается создание личного лагеря.
Подробное ТЗ и план: [`DESIGN_CAMP_SYSTEM.md`](../../DESIGN_CAMP_SYSTEM.md).

## 3. Текущая архитектура ИИ стража

### Сущность
[`BaseGuardianEntity extends PathfinderMob`](entity/BaseGuardianEntity.java:50).
Атрибуты: HP 20, скорость 0.25, `FOLLOW_RANGE` 16, урон 3.
Размер/рендер: 0.6 × 1.8, модель игрока, `clientTrackingRange(8)`.

### Автомат состояний
`GuardianState` (синхронизируется клиенту через `DATA_AI_STATE`):

| Состояние | Условие | Поведение | Оружие |
|---|---|---|---|
| `IDLE` | нет цели | блуждает, ест хлеб, смотрит на игрока | арбалет |
| `RANGED` | цель в 3-12 блоках | держит рубеж, стреляет из арбалета | арбалет |
| `MELEE` | цель ближе 3 | бьёт мечом | меч |
| `PANIC` | HP < 30% | отходит, зовёт союзников | арбалет |

**Важно:** автомат считается в [`tick()`](entity/BaseGuardianEntity.java:259) **после** `super.tick()` — значит, голы принимают решения по состоянию **прошлого** тика.

### Голы
Все боевые гола берут `Goal.Flag.MOVE` + `Goal.Flag.LOOK` → **взаимно вытесняют друг друга**, одновременно работает ровно один.

| Приоритет | Гол | Файл | Роль |
|---|---|---|---|
| 0 | `GuardianRetreatGoal` | [ai/GuardianRetreatGoal.java](entity/ai/GuardianRetreatGoal.java) | паника: отход + зов о помощи |
| 1 | `GuardianMeleeAttackGoal` | [ai/GuardianMeleeAttackGoal.java](entity/ai/GuardianMeleeAttackGoal.java) | ближний бой мечом |
| 2 | `GuardianRangedAttackGoal` | [ai/GuardianRangedAttackGoal.java](entity/ai/GuardianRangedAttackGoal.java) | бой из арбалета, отход, «взвод» перед выстрелом |
| 3 | `GuardianEatBreadGoal` | [ai/GuardianEatBreadGoal.java](entity/ai/GuardianEatBreadGoal.java) | ест хлеб, восстанавливает HP |
| 4 | `RandomStrollGoal` | — | блуждание в покое |
| 5 | `GuardianLookAtPlayerGoal` | [ai/GuardianLookAtPlayerGoal.java](entity/ai/GuardianLookAtPlayerGoal.java) | взгляд на игрока **только в IDLE** |
| — | `GuardianTargetGoal` | [ai/GuardianTargetGoal.java](entity/ai/GuardianTargetGoal.java) | выбор цели (targetSelector) |

### Стрельба
[`performRangedAttack()`](entity/BaseGuardianEntity.java:439):
- ванильная `Arrow` (собственного подкласса нет — подавление отскока признано лишним);
- **упреждение** по скорости цели (два прохода), компенсация гравитации `0.5·g·t²`;
- **точка появления** сдвинута вперёд по направлению выстрела и вниз, чтобы не возникать внутри модели;
- урон = `ceil(скорость × baseDamage)` = `ceil(2.2 × 2.5)` = **6**;
- выстрел только при наведении корпуса на цель (`FIRE_AIM_TOLERANCE_DEG = 12°`);
- «взвод» `PRE_SHOT_DELAY_TICKS = 10` — после полного заряда поза арбалета меняется с `CROSSBOW_CHARGE` на `CROSSBOW_HOLD` (видимый взвод).

### Разворот и ориентация
- **Корпус** (`yBodyRot`) и **голова** (`yHeadRot`) ведутся **раздельно**: голова доворачивается к цели быстрее (30°/тик), но не дальше 75° от корпуса — как в ванильном `LookControl.clampHeadRotationToBody()`.
- Поворот ограничен 20°/тик, сглаживание экспоненциальное.
- **`yBodyRot` ванильными пакетами не передаётся** (клиент считает его сам, из направления движения) — поэтому курс дублируется через `SynchedEntityData` (`DATA_BODY_YAW`, `DATA_HEAD_YAW`), а рендерер подставляет эти значения.

### Движение
- Маршрут строит **ванильная навигация**, скорость считает сам страж в **мировых координатах** — так корпус можно держать развёрнутым к врагу независимо от маршрута.
- Направление движения сглаживается (90°/тик, как у `MoveControl.rotlerp`), скорость разгоняется плавно на ходу, но **старт с места — мгновенный**.
- `MoveControl` перехвачен: он больше не доворачивает курс моба к маршруту (это конфликтовало с разворотом к цели), но сохраняет прыжки через препятствия.

## 4. Правила работы над модом

### Бэкапы — **обязательно перед каждой серией правок**
```
backups/pre_refactor/     — исходники до полного рефакторинга ИИ
backups/pre_smoothing/    — перед сглаживанием движения
backups/pre_standoff/     — перед изменением логики рубежа
backups/_inspect_*.java   — декомпилированные исходники Minecraft для сверки API
```
Бэкапы лежат **вне** `src/main/java` — иначе дубликаты классов ломают компиляцию.

### Проверка API по исходникам, а не по памяти
Декомпилированные исходники 1.20.1 лежат в `backups/_inspect_*.java`
(`LivingEntity`, `AbstractArrow`, `Entity`, `Mob`, `PathfinderMob`, `Projectile`, `ServerEntity`, `GoalSelector`, `HumanoidModel`).
При сомнении — читать их, а не полагаться на память. Актуальные версии можно перезалить через MCP-инструменты.

### Сверка с ванилью (обязательно перед новой механикой)
- `LivingEntity.hurt()` — кулдаун урона (`invulnerableTime > 10 && amount <= lastHurt` → урон отменяется).
- `AbstractArrow.onHitEntity()` — при `hurt() == false` стрела **отскакивает** (разворот на 180°, скорость ×0.1), а не пролетает насквозь.
- `LivingEntity.tick()` / `tickHeadTurn()` — тело следует за направлением движения, коэффициент 0.1.
- `LookControl.tick()` — `resetXRotOnTick()` обнуляет наклон, `clampHeadRotationToBody()` зажимает голову у 75° от корпуса.
- `MoveControl.tick()` — доворачивает курс моба к узлу маршрута (`rotlerp`, 90°/тик) и умеет прыгать.

### Порядок изменений
1. Один логический блок за раз; навигацию, движение и стрельбу **не смешивать** в один патч.
2. Правка — отдельным `apply_diff`; после каждой серии — `gradlew.bat compileJava`.
3. Перед крупным рефакторингом — изменить `AI_CONTEXT.md` и `DESIGN_CAMP_SYSTEM.md`.

### Диагностика
Команда **`/sp_guard [радиус]`** ([`GuardDebugCommand.java`](init/GuardDebugCommand.java:40)) печатает по ближайшим стражам:
состояние, HP, цель и расстояние, углы (yaw/headYaw/bodyYaw/pitch), активные голы, желаемый и фактический курс,
ошибку наведения и признак «можно стрелять», заряд, задержку «взвода», курс и скорость движения, флаги
опоры/коллизии/воды, наличие маршрута, точку сбора.

**Логи:** `run/logs/latest.log` — чат-сообщения команд (`[CHAT]`) тоже пишутся в лог, это удобный способ анализировать поведение без скриншотов.

## 5. Что уже сделано (состояние на сейчас)

- [x] Рефакторинг ИИ: единый автомат состояний вместо разрозненных проверок.
- [x] Навигация вместо самодельного обхода: страж прыгает, выбирается из ямы, обходит стены.
- [x] Правильная формула курса на цель (`atan2(dz, dx)·180/π − 90`) — раньше аргументы были перепутаны, и корпус разворачивался зеркально.
- [x] Синхронизация ориентации тела и головы между сервером и клиентом.
- [x] Упреждение стрельбы, компенсация гравитации, сдвиг точки появления стрелы.
- [x] Плавный доворот корпуса и отдельная, более быстрая голова.
- [x] «Взвод» перед выстрелом, видимый по позе арбалета.
- [x] Сглаживание движения, мгновенный старт с места, снят конфликт `MoveControl`.
- [x] Стражи не стреляют после смерти (`isAlive()`-guard).
- [x] Радиус обнаружения врагов — 20 блоков (отдельная константа `TARGET_DETECT_DISTANCE`).
- [x] **Рабочий рубеж в сущности** (`standoffReached` + `standoffAnchor`): страж сближается **один раз за бой**,
  дальше держит занятую позицию и за врагом не идёт; если враг подошёл вплотную — отходит **на занятый рубеж**
  (якорь в мире, маршрут стабилен). Переход `MELEE ↔ RANGED` рубеж **не** сбрасывает — это устранило качели.
  Сбрасывается только при смене цели, уходе в панику и потере цели. Сохраняется в NBT (`Standoff`).
