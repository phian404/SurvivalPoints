# SurvivalPoints — контекст проекта

> Краткий рабочий контекст для AI-помощника и разработчика. Здесь фиксируются проверяемое состояние кода, технические ограничения и правила работы. Подробные спецификации остаются в `.roo/plans/`.

**Концепция:** [PROJECT_VISION.md](../../../../../../.roo/plans/Architecture/PROJECT_VISION.md) · **Порядок работ:** [ROADMAP.md](../../../../../../.roo/plans/Roadmap/ROADMAP.md) · **Навигатор:** [индекс документов](../../../../../../.roo/plans/README.md)

## 1. Проект и среда

SurvivalPoints — постапокалиптический мод для **Minecraft Forge 1.20.1 / Java 17**.

| Параметр | Значение |
|---|---|
| Minecraft | 1.20.1 |
| Forge | 47.4.28 |
| Диапазон версий | `[1.20.1,1.21)` |
| Java | 17 |
| Маппинги | official (Mojang) |
| Mod ID | `survivalpoints` |
| Основной пакет | `com.phian404.survivalpoints` |
| Генерируемые ресурсы | `src/generated/resources` + `src/main/resources` |

Версия 1.20.1 — жёсткое ограничение. Не использовать API 1.21+, Fabric или NeoForge вместо Forge. Перед применением незнакомого API сверяться с документацией/исходниками именно Forge 47.x и Minecraft 1.20.1; не угадывать сигнатуры.

Основные команды разработки на Windows:

```bat
gradlew.bat compileJava
gradlew.bat runClient
gradlew.bat runGameTestServer
```

Последняя команда запускает Forge GameTestServer для namespace мода; конфигурация `gameTestServer` объявлена в `build.gradle`.

## 2. Карта исходников

Карта сверена с деревом `src/main/java/com/phian404/survivalpoints/` на 2026-11-28. Это ориентир, а не исчерпывающий список классов.

| Пакет / файл | Назначение |

| корень | `SurvivalPointsMod`, константы и слои моделей |

| `entity/` | базовые NPC и страж, движение и скины |
| `entity/ai/` | ИИ стража, рабочие задачи NPC, фермерская сессия, использование предметов |
| `entity/ai/task/`, `entity/ai/crop/` | диспетчер задач NPC и адаптеры культур |

Перед изменением всегда проверять актуальный код и регистрацию нужного компонента. Эта карта не заменяет поиск по исходникам.

## 3. Реализованные подсистемы (сверено с кодом)

### Страж

Основные классы: `BaseGuardianEntity`, `GuardianMoveControl`, `entity/ai/Guardian*Goal`, `GuardianTuning`, `GuardianFeatureFlags`.

В коде присутствуют боевые голы ближнего и дальнего боя, выбор цели, отход/паника, поедание хлеба, движение, диагностика и отладочные команды. Реворк стража ранее был принят владельцем; исторические решения и закрытые пункты — в [GUARDIAN_REWORK_PLAN.md](../../../../../../.roo/plans/Combat/GUARDIAN_REWORK_PLAN.md) и [GUARDIAN_STATE_DECISION.md](../../../../../../.roo/plans/Combat/GUARDIAN_STATE_DECISION.md).

Не считать старые планы реализации актуальным списком незавершённых задач. Перед новой работой проверить код и текущую задачу.

### Данные лагеря и материальная часть

Основные классы: `CampRecord`, `CampPost`, `CampSavedData`, `CampManager`, `CampGenerator`, `CampBlueprintParser`, `CampStructurePlacer`, `CampRadioBlock`, `CampRadioBlockEntity`.

В исходниках присутствуют:
- сохранение данных лагерей и управление ими;
- радио-блок как якорь лагеря;
- генерация/размещение лагерных структур и обработка маркеров шаблона;
- модульные секции ограждений, стойка и варианты материалов;
- ворота на базе ванильной двери;
- автоматический поиск места для лагеря в `camp/site/`.

Автоматический поиск площадок — отдельный серверный механизм. `CampSiteConfig.SITE_AUTO_ENABLED` по умолчанию выключен; не включать его и не менять поведение генерации без прямого запроса. Для точных требований ограждений использовать утверждённые [спецификацию v1.1.7-final](../../../../../../.roo/plans/Fences/SurvivalPoints_Fences_v1.1.7-final.md) и [Visual Reference v5](../../../../../../.roo/plans/Fences/SurvivalPoints_Fences_Visual_Reference_v5.md).

### NPC и фермер

Основные классы: `BaseSurvivorEntity`, `BaseSurvivorNpcEntity`, `CampFarmManager`, `FarmApproach`, `FarmWorkStation`, `FarmerStandWorkGoal`, `NpcItemUse`, `NpcTaskController`.

В коде реализована работа фермера с рабочей станции: NPC обслуживает несколько грядок с одной позиции, использует сессии сбора/посадки, проверяет доступность рабочих позиций, обрабатывает недостижимые грядки и cooldown. Диспетчер лагерной фермы управляет резервированием грядок. Использование предмета NPC вынесено в общий helper.

Для этой подсистемы существуют 10 сценариев в `FarmerSessionGameTests`; см. [TESTING.md](../../../../../../.roo/plans/Testing/TESTING.md). Наличие теста не означает, что он уже запускался в текущем окружении или что визуальная проверка в клиенте пройдена.

## 4. Текущий контекст разработки

Последние коммиты 26–27 ноября 2026 года сосредоточены на поведении фермера и использовании предметов NPC: работа из клетки станции, обработка недостижимой грядки, последовательность сессий, семя в руке и взаимодействия NPC с предметами.

Это описание недавнего направления по истории Git, а не назначение следующей задачи. Следующий приоритет определяет владелец. Не выводить из ROADMAP или старых планов разрешение на самостоятельную реализацию.

## 5. Правила работы

- Не менять игровые механики, баланс, тайминги или визуальное поведение, если задача явно этого не требует.
- Сначала изучить существующую реализацию и повторно использовать текущие классы/контракты. Не создавать параллельную систему без доказанной необходимости.
- Не делать крупный рефакторинг, новые зависимости или инфраструктуру «на будущее» без согласования.
- Для исправления поведения определить конкретный сценарий и критерий успеха; по возможности добавить/обновить GameTest.
- Не считать компиляцию доказательством корректности поведения в игре. Отдельно указывать: compile, GameTests и ручная проверка.
- Перед push проверить diff на незапрошенные изменения, временные файлы и несвязанные форматирования.
- В отчёте перечислить изменённые файлы, причину, проведённые проверки и то, что осталось проверить владельцу.
- Если документ и код расходятся, код показывает текущее поведение, но утверждённое проектное решение нельзя молча менять. Зафиксировать противоречие и запросить решение владельца.
- Идеи, концепции и архивные планы не являются задачами без явного согласования.

## 6. Диагностика и тестирование

Команды и параметры могут меняться — сверять с регистрацией в `init/` и кодом команд.

- `/sp_guard` — диагностика стражей.
- `/sp_camp` — управление/диагностика лагерей.
- `/sp_trace`, `/sp_hang`, `/sp_perf` — диагностические инструменты, если зарегистрированы в текущей сборке.
- `gradlew.bat runGameTestServer` — автоматические Forge GameTests.
- `run/logs/latest.log` — основной лог локального клиента/сервера.

Подробные сценарии, ограничения и отчётность — в [TESTING.md](../../../../../../.roo/plans/Testing/TESTING.md).

## 8. Главное правило

**Сначала понять задачу и текущее состояние кода, затем сделать минимальное проверяемое изменение, проверить его и честно описать результат.** Не угадывать API, не переключать приоритеты самостоятельно и не реализовывать идеи из концепции без согласования.
