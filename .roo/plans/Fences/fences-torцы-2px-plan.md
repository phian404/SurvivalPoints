# План: выравнивание боковых торцов секций (единое сечение 2 px)

Волна чисто визуальная. Не меняет Java, коллизии, blockstates, lang, рецепты.

## 1. Задача

Подогнать боковые торцы проволоки, сетки и металлического листа под основные секции:
привести все четыре материала к единому поперечному сечению **2 px** (`X 7..9`)
и выровнять UV торцевых граней с длинными гранями.

|---|---|---|---|
| [`section_mesh.json`](../../../src/main/resources/assets/survivalpoints/models/block/section_mesh.json:9) | 1 бокс `Y 0..16` | `7..9` (2 px) | **отсутствуют** |
| [`section_wire.json`](../../../src/main/resources/assets/survivalpoints/models/block/section_wire.json:9) | 2 бокса `Y 8..14`, `Y 3..9` | `7..9` (2 px) | есть, UV `[0,3.5,2,9.5]` / `[0,10,2,16]` |
| [`section_sheet.json`](../../../src/main/resources/assets/survivalpoints/models/block/section_sheet.json:12) | полотно `Y 2..16` + рейка `Y 0..2` | полотно `8..8.5` (**0.5 px**), рейка `6..10` | есть, UV `[0,0,0.125,15]` |
| [`section_planks.json`](../../../src/main/resources/assets/survivalpoints/models/block/section_planks.json:9) | 2 доски `Y 10..15`, `Y 2..7` | `7..9` (2 px) | есть, UV `[0,0,2,5]` |

### 2.1. Дефекты, которые устраняются

1. **`mesh` без торцевых граней.** При взгляде вдоль пролёта торца нет вообще — видна пустота.
2. **`sheet` — полотно 0.5 px против 2 px у остальных.** Торец `north` имеет UV `[0,0,0.125,15]`:
   ширина 1/8 текселя (не читается), высота `15` при фактических 14 px (растяжение).
3. **`wire` — UV торцов не совпадают с боковинами.** Торец `v 3.5..9.5`, боковина `v 6..10`:
   на угле рисунок рвётся.
4. **`plank` — сдвиг `u` на 1.** Торец `u 0..2`, боковина `u 1..17`: шов на угле.
5. **`sheet_tongue` — ступенька 1.5 px.** Полотно языка `X 7..9`, полотно панели `X 8..8.5`.
6. **No-op `rotation`** (`angle: 0`) в `section_sheet.json`, `section_wire.json` (×2), `section_planks.json`.
7. **Bedrock-поля** `format_version` и `credit` в `section_sheet.json` (на диске ещё присутствуют).

## 3. Принятые решения

| # | Решение | Значение |
|---|---|---|
| 1 | Сечение | Единое **2 px** (`X 7..9`) у всех 4 материалов |
| 2 | Полотно листа | `X 8..8.5` → **`X 7..9`** |
| 3 | Рейка листа | Остаётся **`X 6..10`** (выступ 1 px с каждой стороны, как сейчас) |
| 4 | UV торцов — правило **U1** | `u 0..2`, `v` — тот же диапазон, что у боковины |
| 5 | Исключение для `plank` | Торец `u 1..3` (светлее, не контрастирует с боковиной) |
| 6 | Языки (`*_tongue.json`) | Правим вместе с панелями, иначе шов переедет на стык «панель ↔ язык» |

### 3.1. Почему U1, а не полный квадрат `0..16`

- **Совпадение по `v`** — торец и боковина показывают одни и те же строки, рисунок непрерывен на угле.
- **`u 0..2` = 2 текселя = толщина 2 px** — масштаб 1:1, без сжатия.
- **`plank` попадает в end-grain** — колонки `0..1` по §7.2 плана текстур и есть тёмная кромка.
- **`wire` не даёт дырок** — `v` берётся из окна, где нить реально есть.
- Полный квадрат `0..16` сжимает всю текстуру в 2 px → мутное пятно, читается как «чужой» участок.

## 8. Валидация

Скрипт-проверка по каждому из 8 файлов:

```
Get-Content -Raw | ConvertFrom-Json
```

Обход `elements[].faces`:

| Проверка | Критерий |
|---|---|
| `maxUV` | ≤ 16 по обеим осям |
| `null` в UV | отсутствует |
| Вырожденные элементы | `from != to` хотя бы по одной оси |
| `format_version` / `credit` | отсутствуют |
| Ссылки на текстуры | все ключи `#x` есть в `textures` |
| `rotation` с `angle: 0` | отсутствует |

## 10. Риски и обходы

| Риск | Митигация |
|---|---|
| `apply_diff` по JSON-моделям падает (`another editor opened in the meantime`) | Правка через PowerShell + `[System.IO.File]::WriteAllText(..., UTF8Encoding($false))` |
| `ConvertTo-Json` разворачивает массивы в столбик | Писать компактный JSON вручную или форматтером |
| `Set-Content -Encoding UTF8` в PS 5.1 добавляет BOM → `illegal character: '\ufeff'` | Только `[System.IO.File]::WriteAllText` с `UTF8Encoding($false)` |
| Here-strings в `powershell -Command` через cmd ломаются на кавычках | Писать скрипт в файл |
| Строковый `Replace` по here-string ненадёжен (табы) | Разбор JSON, не строковая замена |
| Gradle **не валидирует** JSON-модели | Отдельный шаг валидации (§8) |
| Торец `plank` всё равно тёмный | Уже сдвинут на `u 1..3`; если мало — `u 2..4` |
| `sheet` после расширения до 2 px перестаёт читаться как «тонкий лист» | Принято заказчиком (вариант A) |

## 11. Открытые вопросы

1. `sheet` — после расширения до 2 px визуально станет «толще». Если в игре не понравится, вернуть 0.5 px и оставить только выравнивание UV.
2. `plank` — торец `u 1..3`. Если контраст всё ещё велик, сдвинуть на `u 2..4`.
3. `wire` — окно `v 6..10` рассчитано на одну нить в текстуре 32×32 (см. §5 плана текстур). Если `wire.png` перерисуют под две нити, UV придётся пересчитать.
