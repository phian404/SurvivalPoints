# TESTING.md — проверка проекта

> Этот документ описывает доступные проверки и границы их покрытия. Он не является журналом прогонов: результат конкретной проверки фиксируется в отчёте задачи или CI. Не объявляй тест пройденным, если он не запускался и его результат не проверен.

## 1. Команды

Запускать из корня проекта на Windows:

| Цель | Команда | Что подтверждает |
|---|---|---|
| Компиляция | gradlew.bat compileJava | Компиляцию Java-кода |
| Forge GameTests | gradlew.bat runGameTestServer | Результаты зарегистрированных GameTests |
| Клиент | gradlew.bat runClient | Возможность запуска клиента для ручной проверки |

Для GameTests проверяй завершение процесса и итоговый лог в run/logs/. Сам факт старта задачи Gradle не означает успешного прохождения тестов.

## 2. Существующие GameTests

В FarmerSessionGameTests.java находятся следующие 10 сценариев:

| Тест | Проверяемое поведение |
|---|---|
| ring_harvested_from_one_station | Сбор нескольких грядок с одной рабочей станции |
| harvest_only_from_workable_position | Сбор только из позиции, разрешённой FarmWorkStation.canWorkFrom |
| head_turns_are_smooth | Плавность поворота головы |
| two_plants_in_one_session | Посадка нескольких грядок за одну сессию |
| harvest_then_plant_in_two_sessions | Разделение сбора и посадки на отдельные сессии |
| mature_plot_in_cooldown_blocks_planting | Cooldown зрелой грядки блокирует преждевременную посадку |
| full_inventory_ends_session | Завершение сессии при заполненном инвентаре |
| real_farm_harvested_from_one_station | Сбор на геометрии шаблона фермы farm_lvl1 |
| seed_taken_from_inventory_for_planting | Получение семян из инвентаря NPC |
| seed_left_in_hand_between_plantings | Сохранение семени в руке между действиями посадки |

Перед изменением фермерских сессий, рабочей станции, инвентаря или использования предметов NPC запускай этот набор.

## 3. Ручная проверка

GameTests не заменяют проверку в обычном клиенте. Добавляй ручные сценарии к конкретной задаче, если изменение затрагивает:

- рендер, анимации, модели, текстуры или визуальную читаемость;
- поведение, зависящее от реального игрового тика, навигации или окружения;
- сохранение и загрузку мира, если это не покрыто соответствующим GameTest;
- сетевое отображение и взаимодействие нескольких игроков;
- длительное поведение в существующем мире.

Ручной сценарий должен содержать начальные условия, действия и наблюдаемый ожидаемый результат. Не копируй сюда архитектурное описание системы или исторические чек-листы уже закрытых этапов.

## 4. Отчёт о проверке

Для каждой задачи указывай отдельно:

- compileJava: пройдено / ошибка / не запускалось;
- runGameTestServer: пройдено / ошибка / не запускалось / неприменимо;
- ручная проверка: что именно проверено и в каком окружении;
- оставшиеся ограничения или непроверенные сценарии.

Основной локальный лог клиента/сервера: run/logs/latest.log. Для дефекта прикладывай релевантный фрагмент лога, шаги воспроизведения и скриншот/видео, если визуальная составляющая важна.

## 5. Границы и правила

- Компиляция подтверждает только успешную компиляцию, а не корректность поведения.
- GameTests покрывают только явно реализованные тестовые сценарии.
- Успешный GameTest не подтверждает визуальное качество, мультиплеерное поведение или отсутствие регрессий во всех игровых ситуациях.
- Не изменяй механику ради упрощения теста.
- Если тест устарел относительно реализации, сначала зафиксируй расхождение; не переписывай ожидания так, чтобы скрыть регрессию.
