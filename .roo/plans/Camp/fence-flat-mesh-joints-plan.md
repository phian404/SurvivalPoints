# План: плоская сетка и стержни на концах ограждения

## Цель

Для любой непрерывной линии сетчатого забора показывать объёмные стержни только на свободных концах линии/ветви. Все блоки, соединённые с соседями, включая внутренние участки, углы и узлы ветвления, должны выглядеть как плоская сетка без объёмных крестов и лишних торцевых элементов.

Пример: в прямом ряду из трёх блоков стержни видны на двух внешних концах; внутренние стыки между блоками остаются плоскими. Длина ряда не фиксирована.

## Ограничения

- Не заимствовать модели, текстуры или геометрию стороннего мода; использовать оригинальные ресурсы SurvivalPoints и ванильные принципы соединения.
- Сохранить соединяемость `camp_fence` и совместимость с Forge 1.20.1.
- Не менять генератор лагеря.
- Добавлять Java-логику только если текущих свойств соединения и multipart-моделей недостаточно для распознавания свободных концов.
- Не подключать модель целого многоблочного пролёта к каждому отдельному блоку.

## Текущее состояние

- `camp_fence` наследует соединительные свойства `IronBarsBlock` и использует направленные свойства `north/east/south/west`.
- `camp_fence.json` собирает модель из multipart-частей по этим свойствам.
- Боковая и центральная модели наследуют ванильные модели `iron_bars_side` и `iron_bars_post`.
- Центральная ванильная модель формирует крест; боковая добавляет торцевую геометрию.
- Текстура сетки назначена слотам `bars` и `edge`, но геометрия ванильных моделей сохраняет объёмные узлы.

## Правило отображения

- Свободный конец линии/ветви: поставить оригинальный стержень/краевую деталь.
- Стык с одним или несколькими соседями: оставить только плоскую сетку; не показывать центральную крестовину.
- Прямой участок любой длины: стержни только на двух концах.
- Угол и Т-/крестообразный узел: сам узел плоский; стержни остаются только на концах отходящих от него ветвей.
- Для одиночного блока все стороны считаются свободными; его отображение должно быть отдельно проверено, чтобы модель не вернула крест.

## План реализации

1. Проверить доступные свойства `IronBarsBlock` и выразительность multipart-условий для различения свободных направлений и соединённых сторон.
2. Создать оригинальные модели плоской сетки и краевого стержня на основе существующей текстуры; не использовать объёмные торцы ванильной модели.
3. Пересобрать multipart `camp_fence.json`: соединённые направления отображают плоские участки сетки; свободные концы — краевые стержни; центральная модель не создаёт крест.
4. Если ресурсных условий недостаточно, остановиться до изменения Java и согласовать минимальный способ вычисления свободных концов. Не добавлять динамический рендер без отдельного обоснования.
5. Проверить топологии: одиночный блок, ряд из 2/3/нескольких блоков, L-образный угол, Т-стык, крестообразное ветвление и замкнутая группа 2×2.
6. Собрать проект и проверить в клиенте; убедиться, что стержни находятся только на свободных концах, а плоские полотна не имеют зазоров или заметного мерцания.

## Критерии готовности

- В прямом ряду длиной N стержни есть только на двух крайних концах; все внутренние стыки плоские.
- Во всех ветвящихся конфигурациях объёмные узлы не образуют крестов; стержни видны только на свободных концах каждого плеча.
- Сетка визуально непрерывна, без дыр, объёмных внутренних граней и z-fighting.
- Сборка проходит, результат подтверждён проверкой в игре.
- Не используются сторонние защищённые ресурсы.
